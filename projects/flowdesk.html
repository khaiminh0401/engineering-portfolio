Overview and stack

FlowDesk aims to become a workspace and workflow management application. The current implementation establishes engineering foundations and a live connection view; it does not yet implement the advertised business workflows.

Architecture and module boundaries

One Spring Boot API deployable, one Angular SPA and one PostgreSQL database form the starting modular-monolith architecture. Current backend runtime contains the application entry point and shared.api info endpoint. Business modules identity, workspace, project, task, approval and audit are proposed boundaries, not implemented packages. The frontend has a shell and features/dashboard. See diagram and boundary notes and ADR-0001.

Authentication and authorization

No application authentication, session lifecycle, refresh rotation, workspace RBAC or tenant isolation is implemented at this commit. ADR-0002, the proposed identity contract, threat model and acceptance scenarios are design artifacts. Their presence and merge do not prove runtime enforcement or human approval of all policy choices. Python probe mechanics are tooling, not application security tests.

Database design

V1 creates app_users: UUID primary key, unique non-null email (255), non-null display_name (150), and non-null created_at timestamp with time zone defaulting to NOW(). There is no password column, session table, workspace schema, user API or JPA entity. Hibernate ddl-auto=validate is configured, but without entities it cannot validate this table against an ORM mapping. Integration tests exercise SQL constraints directly. Future schema changes need new migrations.

API contracts and UI behavior

  • GET /api/v1/info returns application FlowDesk and stage sprint-0; implemented by InfoController.
  • GET /actuator/health provides the health status; configuration exposes health/info. The dashboard requires health UP and valid non-empty info strings before showing connected.
  • openapi.yaml describes the implemented API. The separate identity proposal is not a list of available endpoints.
  • The connection service joins info and health requests with a five-second timeout. The component uses signal-based loading/ready/error states, cancels a preceding subscription, cleans up on destruction, disables the button while loading and provides a safe retry message.

No task/project API, pagination workflow, workload caching, message broker or LLM integration was found in the runtime tree.

Testing strategy and verification limits

Controller tests isolate the info contract. FoundationIT starts a real PostgreSQL 17 Testcontainer and exercises Boot, HTTP, Flyway and SQL constraints. Angular tests cover the shell, routing and connection boundary. Playwright includes live proxy/API/database connectivity, safe error/retry, malformed response and mobile viewport scenarios; named failure cases intercept the network boundary.

The test strategy separates these scopes. CI run 41016120486 reports success on the audited commit. This portfolio task inspected source and workflow status; it did not rerun the application suites or independently inspect all job logs. No coverage, load capacity, performance gain or security assurance is inferred.

Development workflow

The project README documents Java 21/Maven 3.9+, Node 22.12+ within 22.x, Chrome and Docker requirements; trusted local environment configuration; Compose database startup; backend/frontend startup; Maven verify; frontend lint/unit/production build; and live Playwright checks. CI has API, web and E2E jobs. Compose is local database infrastructure, not evidence of containerized application deployment or Kubernetes hosting.

Planned milestones and decisions

The roadmap orders M1 identity/workspace, M2 projects/tasks, M3 approval/concurrency/audit, M4 broader quality and measured performance, M5 deployment/observability, and M6 portfolio release. These are planned scopes, not delivery promises. Reconcile the stale status before using the roadmap operationally.

ADR-0001 accepts a modular monolith to reduce deployment and consistency complexity at the current scope. Independent service scaling is a trade-off; package boundaries need discipline as domains arrive. ADR-0002 remains Proposed. See the decision index.

Interview walkthrough

Start with the info contract, follow the Angular service's unknown-payload validation into explicit UI states, then inspect the PostgreSQL constraint tests. Explain why the architecture starts with a monolith and why identity design is not yet a delivered authentication feature. These are concrete reviewable examples; production traffic handling remains a separate candidate-confirmed experience claim.
